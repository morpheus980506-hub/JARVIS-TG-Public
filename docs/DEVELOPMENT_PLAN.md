# Development Plan

## V0.7 当前版本

- 应用、API 和软件包统一为 0.7.0。本机单用户试用支持按任务显示进度、自动生成对话标题，以及改进的聊天输入区。此前的行程查询质量和历史恢复见 [V0.6 质量记录](ADVICE_QUALITY_PUBLIC5_2026-11-10.md) 和 [连续操作记录](CONTINUITY_AUDIT_PUBLIC4_2026-11-10.md)。

## V0.6 alpha 已完成基础

- 用户挑刺的12组复现路径已修复并复测，需求按消息顺序更新、相对日期按原消息时间解析；取消保留输入，刷新恢复待生成状态，英文完整需求进入结构化流程。长回复与模型上下文限制分开。行程按到达时刻和路线核验结果安排，餐厅使用饮食排除条件与地点周边；导出保留全预算及待核验事项。详见[修复记录](USER_AUDIT_FIXES_2026-11-10.md)。

- 具体餐厅追问直接继承目的地并执行只读地点查询，返回真实店名、地址和地图链接；联网资料兜底与未查询成功状态分别展示，不编造实时营业或价格。

- “我的行程”汇总各对话最新保存安排，可搜索、查看详情并回到来源对话修改。详情状态与主聊天独立，右侧行程仍只跟随当前对话；兼容旧对话日程，不展示已删除对话遗留的历史计划。

- 聊天后隐藏开场建议；完整规划保存后追加可恢复的完成反馈与查看入口。区域目的地先确定具体城市，没有地点的结果明确保留为草案。行程页采用按天列表和统一页签，重复说明折叠。
- API接口页与每家配置窗口提供中英文接入教程，含官方入口、字段填写、功能验证与常见问题，覆盖现有10项服务。

- 版本为0.6.0-alpha.1（Python包版本0.6.0a1），界面显示V0.6 alpha。
- 已选候选支持编辑估算金额、数量、分类和备注；保留原始平台报价及链接。候选缓存过期不影响编辑本地估算，行程条件变化后的待核对标记须明确确认才能清除。
- 完整规划可停止并保留旧行程；取消或切换对话后，迟到结果不会覆盖当前状态。生成结束至保存确认期间保持等待状态；保存未确认时可重试保存，不必重查供应商。
- 多城住宿查询保留超时前成功的候选，标记部分完成；单城首家不可用或无结构化候选时尝试其他已配置平台。前台显示当前步骤、等待时间和停止入口，中英文进度均可读。
- 同一对话的聊天、重命名、费用和行程更新共用进程内锁，防止元数据相互覆盖；不同对话独立。该锁不替代未来多进程部署所需的数据库并发控制。
- 182项后端测试、41项前端测试及生产构建通过。已真实联调候选加入、费用编辑、恢复和导出；浏览器、手机App及打印/PDF视觉验收仍待完成，复杂规划延迟仍需继续优化。

## V0.6 基础版本

- 统一前端、后端、健康接口与MCP客户端版本为0.6.0，界面显示V0.6。
- 聊天可发起飞猪/美团只读查询，按平台先后回传结果；滴滴意图将地点条件交给现有确认流程。真实酒店候选进入结构化规划，缺失价格保留为空。
- 候选加入当前对话后记录用户填写的估算单价与数量；去重、移除、超预算提示和费用重算均基于持久化选择。未选费用明确不包含在已选合计中。
- 完整TripRecord与对话绑定，右侧摘要、我的行程、已选候选和费用共同恢复；最新保存安排及已选项目进入后续对话上下文。异步切换历史不会把旧对话结果写入当前对话。
- 城市日程使用高德地点候选并核对相邻步行路段；自驾先建议每日停留城市，再核对各段路程，超过6小时提示调整。自驾途中住宿按每日城市及入住日期查询，避免错查最终目的地全部晚数；目前单次最多覆盖3段住宿日期，其他段须继续查询。
- 自驾地理编码会验证行政区匹配，省级模糊结果不能作为城市路线。相邻路段共享已验证坐标并控制请求频率；动态路程时间不缓存为静态坐标数据。
- 已有自驾标题可重新核对路线；天气手动刷新、失败保留旧结果、按出发日期检查覆盖。复核资料进入后续重排上下文。支持Markdown导出、浏览器打印/PDF、停止回复。
- 限量并发读取多城住宿，可选摘要采用快速路径并限制6秒等待；停止回复不会释放尚未完成的后台查询容量，防止重复操作累积进程。
- 核心接口流程已有真实服务联调；浏览器端整套交互、移动端和手机App跳转仍需验收。开放/预约时段、预订房态及最终价格没有统一验证，不宣称完整行程已经全部可执行。持续监控与自动通知尚未实现。

- 两家均增加加密配置与官方密钥获取入口，使用锁定版本官方客户端，只提供旅行查询和到平台查看详情。
- 主聊天“酒店·预订”与住宿页共用查询组件，平台并行、独立结果与重试。模拟住宿预算折叠保留，不假冒真实报价或库存。
- 已完成七项现有服务基础盘点；用户已配置滴滴、飞猪、美团，三家真实只读查询通过。已根据真实返回修正飞猪详情域名与美团旧式短链兼容。手机跳转及其他查询品类仍待按需验收，详见[API/MCP接入清单](API_CONNECTIONS.md)。支付、人流热力仍未接入。

## 滴滴出行

- 设置 → API接口增加滴滴个人 MCP Key 及官方领取入口；地图 → 出租车增加“滴滴查价”侧栏，支持上下车点搜索与确认、车型预估、App跳转与二维码，中英文界面。
- 使用正式 MCP 服务；上下车坐标不复用高德或自动定位估计值，重新由滴滴搜索并让用户选择。地点保留10分钟、报价保留2分钟，密钥更换后旧数据失效。
- 订单及支付由用户在滴滴 App 确认。用户密钥的地点/车型预估查询已通过，手机跳转仍待验收。参考[官方文档](https://mcp.didichuxing.com/api)。

## 设置与服务信息架构

- 设置分为界面偏好、API接口、支付方式、操作确认、运行记录；行程操作确认不再称为授权中心，也不要求先生成行程才能查看。
- API接口页支持现有模型/地图/联网/航班/天气服务配置，状态为“已配置”而非已验证连接；密钥留空保留旧值，不回显。
- 配置覆盖由Windows DPAPI加密保存至本机，已加入Git忽略；保存后更新模型/工具网关，后续请求生效，地图JS Key变更需刷新前端。
- 用户明确选择支付先保留入口，未接入支付服务商；支付页不收集账户或银行卡数据，不模拟绑定成功。

- 同区域请求在前后端去重，不同区域后端限量并发，减少拖动/缩放时的等待和无效请求。
