# V0.6 public.3：扩大挑刺范围与修复

日期2026-11-10；应用/API/JS版本`0.6.0-public.3`，Python包`0.6.0rc3`。本轮从public.2继续检查语义、生成链路、工作区、异常输入及并发，不宣称穷尽所有输入或完成全部界面验收。

## 本轮确认并修复

| 类别 | 原问题 | 修复与验证 |
| --- | --- | --- |
| 天气与日期 | 问“明天天气怎么样”会把出发日期改成明天。 | 天气、气温等资料的日期不写入出发日期；真实对话中询问明天天气后原出发日保持不变。 |
| 局部保护 | “先别改预算，人数改成3人”会忽略人数修改。 | 只保护指定字段，其他明确修改继续应用。 |
| 金额作用范围 | “人均2000，总预算4000”重复乘人数；“3人总预算6000”可能取3元。 | 按每个分句确定人均/总额，从预算标签后提取金额；支持科学记数并拒绝非有限值。 |
| 未决定与撤销 | “人数/日期/预算未定”仍沿用旧值；撤销修改不生效。 | 清空对应未定字段；保存有效修改的历史快照，可撤销最近修改，跳过中间无修改的询问，也可撤销取消和重置。 |
| 日期边界 | 昨天仍可规划；跨年未写年份按旧年处理；极端日期可能溢出。 | 新出发日不能早于北京时间今天；未写年份取原消息时间之后的下一次对应月日；无效日历和超出完整行程范围的日期要求补充。明确写旧年份仍按过期日期处理。 |
| 家庭人数 | “2大1小，还有1个婴儿”少算婴儿；负数家庭成员被忽略。 | 合计组合中的人数，非法计数要求补充；票务年龄与资格不由总人数代替。 |
| 正式生成 | 已确认1人仍可能被文字中的旧“2人”覆盖；纯文字大天数可绕过上限。 | 正式结构化字段优先；需求模型同步校验天数1—60、人数1—100、预算有限且为正，生成前校验日期范围。真实生成已验证1人保持不变。 |
| 咨询与日程 | “先别改”的咨询回复出现D1/D2时覆盖旧行程，或刷新后被恢复成新行程。 | 未承诺修改的咨询不能更新日程，也不能误标修改待完成；明确保存“没有日程”与旧数据缺字段的兼容恢复分开。前端正确处理空日程响应。 |
| 工作区预算 | 清空预算后费用面板仍显示旧预算上限。 | 工作区同步清空旧上限，不以历史数额代替未确定预算。 |
| 候选复核 | 没有绑定正式计划，或显示上一版计划时，旧酒店候选可能不提示条件已变化。 | 候选的复核依据当前已确认条件；选择及确认费用时也使用同一条件来源，不把旧计划的城市/日期当成当前条件。 |
| 酒店查询隔离 | 查入住/退房日或3人5天的酒店时，改坏旅行本身的日期或人数。 | 仅商品查询的条件不写入旅行条件；明确修改行程的指令仍可正常应用。 |
| 酒店日期依据 | 只问“查杭州酒店”时，模型自填未来日期也可能查询；重置后仍可能沿用旧城市。 | 日期必须来自用户、有效的已确认日期或明确晚数推算；支持完整日期、紧凑日期范围与中文晚数。排除被改掉/未定日期；模型查询上下文从重置后的会话开始。 |
| 天气并发 | 刷新途中修改目的地但Trip ID相同，旧天气仍可能写回。 | 写回前比较当前目的地、出发日、天数与修改状态；变化返回409，保留上次资料。修改尚未完成时不把旧行程天气当成更新结果。 |
| 导出 | 仅聊天产生的日程没有TripRecord时，导出遗漏已确认总预算和旅行条件。 | 导出这些条件并明确没有全行程费用估算，不把已选费用等同于完整费用。 |
| 异常请求 | 空白用户消息、助手结尾的请求、空白标题、重复日程编号可进入后续逻辑；无穷数可能导致序列化失败。 | 在请求入口拒绝无效数据；金额及总成本必须有限；校验响应不回显提交的完整输入，非法JSON数值可得到422。 |
| 并发确认 | 同时同意和拒绝一条待确认操作，两者可能都成功。 | 数据库按“仍待确认”条件原子更新，只有一个请求成功。本项仅在隔离数据库测试，不触发真实业务操作。 |
| 错误反馈 | 输入错误仍提示反复重新打开对话，规划入口只显示状态码。 | 中英文分别显示可用的服务端说明或检查输入提示；不渲染错误体中的原始提交值。 |
