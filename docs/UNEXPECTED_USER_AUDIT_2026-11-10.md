# V0.6 public 非预期用户表达专项测试

测试日期：2026-11-10。被测版本：`0.6.0-public.1`，产品提交`e365cb3`。

后续修复与复测见[V0.6 public.2修复记录](UNEXPECTED_USER_FIXES_2026-11-10.md)。下文保留修复前结果。

## 结论

本轮扩大了口语、否定、假设、模糊条件和连续纠错测试。发现会静默改写旅行条件的高优先级缺陷，当前版本不能据上一轮回归通过就视为自然语言交互稳定。本轮只测试与记录，没有修改产品逻辑，也没有升级版本或覆盖公开测试标签。

共70条独立解析表达，其中41条与预设交互预期不符；这是表达层面的偏差数，不是41个独立缺陷，也不是所有用户输入的失败率。另完成49次真实本机流式对话请求，包括20组独立的“完整条件→边界追问”、一组7轮连续纠错和一组2轮独立的摘要污染验证。所有这些请求返回HTTP200，业务条件仍有错误，说明仅验证请求成功不足以验收。

基准条件：温州→哈尔滨，2026-12-01出发，3天，2人，总预算10000元，偏好美食。独立表达测试均从相同基准开始。实际流式测试使用服务器恢复的历史逐轮提交，不用客户端伪造助手回复。

## 优先修复的问题

| 编号 | 优先级 | 用户输入与真实结果 | 应有行为 |
| --- | --- | --- | --- |
| U01 | P1 | “行，那你说说现在到底是什么条件？”：回复仍写温州→哈尔滨，但`collected`和`trip_request`变为“你说说现在→底是什么条件”。GET恢复后错误仍在，ready仍为true。 | 普通摘要问题不能修改路线；回复、正式请求与保存结果必须一致。 |
| U02 | P1 | “如果改去成都会不会更贵？先别改”：目的地被保存为“成都会不会更贵”，仍可生成。 | 识别假设与暂不修改，保留哈尔滨；可回答比较或追问。 |
| U03 | P1 | “这趟旅行取消了，别再规划了”与“之前的条件都作废，我们重新开始”：均继续返回旧需求和生成入口。 | 取消应暂停当前规划；明确重新开始应清空有效条件。保留历史记录不等于继续规划。 |
| U04 | P1 | “12月8日回来，出发日期先不变”将出发改为12月8日；“博物馆是12月5日开馆的，行程不改”将出发改为12月5日。解析层“两日出发、六日回来”还会取回程日期。 | 区分出发、回程和资料中的日期，不自动覆盖。 |
| U05 | P1 | “12,000元”变12元；“8k人民币”变8元；“不是5000，是8000元总预算”仍为10000元。另一种“预算不是5000，是8000元”反而取5000元。 | 先理解数值和否定修正；不能确定时澄清。 |
| U06 | P1 | “两个大人，一个小孩，还有一个婴儿”变1人；“-2人”变2人；“-100元”变100元；“2.5天”变5天，同时触发错误日期和过期提示。 | 人群组成正确计数；非法或不支持的小数/负数应解释，不截取尾数或去掉负号。婴儿票务规则应另行确认。 |
| U07 | P1 | “成都或者重庆，还没定”被当成单个目的地；“目的地还没定”被保存为城市“还没定”；“哈尔滨和长春，两个都要”也被当成单个城市。 | 二选一和未决定应澄清；多城市应有明确结构或说明当前能力并确认落脚点。 |
| U08 | P1 | 连续说“不去哈尔滨→目的地还没定→那就重庆吧”，系统停留在“还没定”，无法用正常回答恢复。随后预算纠错仍取错值。 | 追问后的补充应修复当前字段，不应要求用户适应特殊句式。 |
| U09 | P1 | “我手机预算3000元，旅游预算不变”将旅行总预算改成3000元。解析层“另外一趟想去上海，先别改这趟”会改当前目的地。 | 区分当前旅行与其他话题/另一趟旅行，不混入当前条件。 |
| U10 | P2 | “不想以美食为主了，主要看博物馆”仍以美食为正向偏好，另加“不想以美食为主了”的约束，未正确反映新重点。 | 更新偏好，避免同一事实正反并存。 |
| U11 | P2 | 英文“Change the destination to Chengdu, keep everything else.”仍为哈尔滨；解析层英文改出发地、人数增量、天数减量和取消也存在未响应。 | 英文编辑和取消具备与中文一致的语义，不能只支持初次英文完整条件。 |
| U12 | P2 | 解析层预算/天数/日期区间会取一个值，部分尚未确定的日期仍沿用旧值；“交换出发地与目的地”未响应；“预算不限了”未清除旧上限。 | 支持范围或澄清；明确操作不能静默忽略。 |

U01至U11均至少有一项真实接口复现。U12及表中明确标注“解析层”的扩展表达只完成本地解析检查，不能冒充全部已走完整界面流程。

## 连续追问实录摘要

1. 完整基准条件：正确收集温州→哈尔滨、3天、2人、10000元。
2. “不去哈尔滨了”：正确清空目的地。
3. “也不去成都，目的地还没定”：错误设置目的地“还没定”。
4. “那就重庆吧”：仍是“还没定”，未恢复。
5. “预算不是5000，是8000元”：错误设置5000元。
6. “不是三天，改成五天”：天数正确变5天，其他错误仍在。
7. “行，那你说说现在到底是什么条件？”：触发新的路线污染；回复与正式请求进一步不一致。

独立两轮复现排除了连续错条件的影响：即使直接在正确基准后询问摘要，也会发生U01；重新GET对话后仍持久化错误路线。

## 正常边界与测试限制

- 无效日期2027-02-30会要求补日期；0元预算会给校验提示；中文人均两千、全角数字、四天三晚等部分表达正确。不是所有异常表达都会失败。
- 临时对话重命名：空白和161个表情返回422，正常短标题返回200。HTML样式标题可作为字符串保存；现有React标题插值没有直接HTML注入，不能仅凭接口接受该字符串就报告XSS。未做浏览器执行验证。
- 全部临时对话已删除，清理均返回204。本轮未生成正式旅行计划，未下单、付款或修改设置、密钥及原有用户历史。
- 无浏览器控制工具，本轮没有验证真实点击、地图渲染、窄屏、动画或打印。49次真实请求是接口对话流程，不能称为49次浏览器人工验收。
- 41/70来自刻意挑选的非预期表达，不能外推总体准确率。范围等表达的验收标准是“不擅自选定单一值”，不限定必须使用空值这一种实现。
